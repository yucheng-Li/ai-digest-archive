### AI & I by Every: How Anthropic Uses Claude Fable 5 With Mike Krieger

**The Takeaway**：Fable 5 把 AI 从"协作工具"变成了"可以整夜托付复杂任务的队友"，工程师的价值随之转向意图表达、验证体系和结果所有权。

Mike Krieger 是 Anthropic Labs 负责人、Instagram 联合创始人，从 CPO 转回一线 builder 后用 Fable 5 工作了数月。他的核心体验："现在它真的像一个可以委派大量工作的队友（a teammate that I can delegate a lot of work to）"——晚上把复杂任务交给 Claude 就去睡觉，凌晨两点任务就已完成；中途远程服务宕机，模型会自己搭一个 mock backend 绕过去、记录在案，等服务恢复再修正。

几个反直觉的细节：他周末用 Claude Code 一次性（one-shot）建了个人媒体追踪 app，还实现了"从软件内部修改软件"——长按聊天入口提出修改请求，由 managed agents 接单、Vercel live preview 预览。他对比：功能量级相近的 Instagram v1 当年花了他五个通宵。验证是他反复强调的关键：要求每个 PR 附上完整截图集或视频，甚至直接给 Claude 一段录屏加 ffmpeg，它会逐帧发现"这个动画有卡顿"并去修复。

关于"软件工程是否终结"，他的回答是"变了，而不是没了"：写代码这部分"已经走得非常远"，但需求判断、生产环境直觉、对结果的所有权依然属于人。他也坦承转型有痛感："我以前会梦见代码，醒来想到一个优雅的解法——那种体验确实过去了。优秀的工程师同时怀着失落和'我现在能完成海量工作'的兴奋，两种想法只能同时抱着。"

最硬核的案例是 Dynamic Workflows：他周末跑了一个 Python 到 TypeScript 的全代码库移植，workflow 自动编排"深度理解 → 写 spec → 逐模块翻译 → 增量测试 → 对抗测试 → 查漏"，回来时移植已完成且"在某些方面更好"。关于定价他给出的判断标准是：别只看单轮成本，要看"完成到你满意为止"的总成本——Fable 省掉的是后面九、十轮"不对，我要的不是这个"。
