**Claude Blog — Claude Code now supports artifacts**

Claude Code 从即日起可以把工作进展沉淀成 artifact，把会话里干的活变成一个个实时、可分享的可视化网页——PR 走查、系统讲解、dashboard、发版 checklist——并且会随着会话推进自动更新。它基于你整个会话的完整 context 来构建：你的代码库、连接的 connector、对话本身。比如一个事故排查页面，可以把失败的测试、背后的函数、监控工具里的错误率飙升，以及刚跑出来的根因推理，全都聚到一起，不需要你自己接数据源或搭基础设施。

每次发布都是同一链接下的一个新版本，带版本历史可随时回滚，还有 gallery 管理你做过的所有 artifact。官方内部测试中最常见的用法是调试：工程师在站会前发起事故调查，Claude Code 翻完日志后发布一个 artifact（时间线、可疑 commit、错误率曲线），站会开始时它已经随调查进展重新发布了两次。每个 artifact 默认仅作者可见，可在准备好后分享给团队和组织，但只有组织内已认证成员可见、无法对外公开。该功能目前以 beta 形式面向 Claude Team 和 Enterprise 组织开放。

## 🎙️ 播客

**Training Data — Memory and Continual Learning: Engram's Dan Biderman and Jessy Lin**

**核心 takeaway**：模型最大的瓶颈已经不是原始智能，而是"持续学习"——如何把每个公司、每个团队独有的 context 真正烧进权重里，而不是每次都靠堆 context、读文件来临时应付。

Engram 两位联合创始人 Dan Biderman（神经科学背景）和 Jessy Lin 正在做一件和前沿大厂"造一个越来越大的通用模型"完全相反的事：为每个团队、最终为每个人，训练专属的小模型。他们用 LoRA、prefix、稀疏架构等各种 adapter 微调手段，配合 SFT、RL、on-policy distillation，把团队多年积累的文档和交互变成训练信号，让模型像一个在公司干了好几年的老员工那样，"天然就知道"这些事，而不是每次都去搜索框里查"我昨天在干嘛"。

最反直觉的一个数字：Jessy 说，把这类关于人、团队、组织优先级的隐性知识训进权重后，"前沿模型要烧 10 万 token 才能回答的问题，模型可以在 100 token 内答出来"——可能带来两个数量级的推理成本下降。他们还把这套方法称为"RAG killer"：RAG 的真正难点其实不在于存什么、存哪，而在于"怎么知道该查什么"——而很多跨文档的联想，只能发生在权重里。

Dan 用一个犀利的类比收尾：给一篇维基百科文章做 KV cache 可能要占 80GB 显存，而一个 70B 模型把整个互联网压进去也才 100GB 左右——"梯度下降能把海量信息打包进极少的数字里"，这正是他们想用离线计算把那 80GB 压缩上千倍的方向。
