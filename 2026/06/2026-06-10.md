### Claude × Apple Foundation Models 框架（Claude Blog, 2026-06-08）
- 链接：<https://claude.com/blog/claude-for-foundation-models>
- 发布一个 **Swift 包**，让 Apple 开发者通过 **Apple Foundation Models framework** 直接调用 Claude。
- 玩法：on-device 小模型负责快路径（提炼、抽取、本地 prompt），需要多步推理 / 代码生成 / 联网搜索 / 数据分析时 **handoff 给 Claude**，对用户是同一个体验。
- 关键工程点：Apple 框架用 `@Generable` 注解返回 **typed Swift 值**，Claude 调用拿到的是结构化输入而不是 raw user text；包内自动处理流式、tool call、structured response 回 SwiftUI。
- 覆盖平台：iOS / iPadOS / macOS / visionOS / watchOS **27** （明天起可用）。
- 信号：Anthropic 正式把 Claude 嵌进 Apple 一等公民的开发者通道，绕开 ChatGPT/Apple Intelligence 那条独家路线。

## 三、播客

### No Priors — Building an AI Guardian for Enterprise with Onyx Security CEO Maxim Bar Kogan
- 链接：<https://www.youtube.com/watch?v=QDsbFLEt9ro>（2026-05-28 上线）
- 嘉宾：**Maxim Bar Kogan**，Onyx Security 联合创始人 & CEO，以色列出身，研究员 / 数学家 / 工程师组成的团队，做 "**用 agent 看 agent**"。
- 关键观点 / 数据点：
  - 当年押注 **AutoGPT**，公司差点提前烧光钱；真正起飞是 reasoning model 出来 + **Claude Code** 成为第一个被广泛使用的自主 agent + Cowork / OpenCloud 跟上。
  - 当下企业 AI 工作量结构：**autonomous 编码 agent ≈ 50%+**、低代码自动化 ≈ 45%、企业自建 first-party agent ≈ 2%；其中 **autonomous 增长最快**，但几乎"裸奔"上线。
  - 传统安全栈失效的根因：**我们故意给 agent 人类等价权限**（要它代替工程师干活），所以 identity-based 控制天然失灵；endpoint / API 安全工具又看不到 agent 的意图（不知道它"想"删数据库还是"误删"）。
  - 代理 / proxy + policy engine 那一套不够 —— 抓到数据不是难点，**难点是"现在该不该让它干"这个判断**，需要一个能理解世界上最聪明模型在想什么的 underwriter。
  - Onyx 的解法：**自己训模型 + 训 agent** 做 overseer，做成 "AI control plane" 产品 —— 把企业里所有 AI / 自主 agent 接入一个统一监督面。
  - 行业观察：企业不愿把 agent 行为历史数据交给 Anthropic / OpenAI，因为知道这些是 "data-hungry" 公司会拿去训模型，这是中立第三方监督公司天然的机会。
- builder takeaway：如果你在做 agent 平台或者大 enterprise 的 agent 上线方案，把 "**permission = human-level, oversight ≠ human-level**" 这个错位作为核心设计前提。
