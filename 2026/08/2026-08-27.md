### Training Data — Parallel's Parag Agrawal: Building a New Web for AI Agents

**一句话结论：给 agent 用的搜索不是把 Google 包一层 API，而是要把"人类点击数据"当成 bug 从头重建的另一套 web。**

说这话的是 Parag Agrawal —— Twitter 卖给 Elon 之前的最后一任 CEO，现在回到创业者身份，创立了 Parallel Web Systems，做的正是给 AI agent 用的搜索基础设施。他一开始就把从 Twitter 学的东西大部分扔掉了：Twitter 是一个早已跑通 PMF、有几亿用户每天用三十多分钟给你反馈的超大规模生意；Parallel 则是在为"几年后才会出现在互联网上的新客户"造技术，两种状态下的做事方式完全不同。

他最反直觉的论断是那句开场白："我们在 Parallel 的观点是，人类点击数据是个 bug。做实际工作的 agent 应该依赖 agent 的反馈，而不是人类的反馈。"这不只是姿态。他解释了为什么互联网上到处是那种"XX 公司最新财报是多少"的 SEO 农场页面：真正权威的数字在 SEC 那份要加载三秒半、答案埋在第 73 页的 PDF 里，而人是懒的。于是市场自然长出一批加载快、答案在首屏、99.99% 正确的中间页。"你可以管它叫 slop，也可以说它是在迎合懒惰的人类并且 SEO 做得很成功。"而 agent 不需要这个折中——直接把最权威来源的那一段摘出来送进 context window 就行。

这也决定了 Parallel 的技术形状：每一次查询本质上是"从一万亿个网页里给我一千个 token，并且保证是对的那一千个"。他们上周把这件事从 3 秒压到了 200 毫秒（产品叫 TurboNow）。公司前两年刻意放弃延迟这一维，只死磕质量和成本，因为"蒸馏成小模型是已知的工程，不是未知的研究"，等质量和成本都拿下了再回头做延迟。他也不认为模型公司会顺手吃掉这块：预训练爬虫不耐烦等 JavaScript 慢慢加载，而 Parallel 是完美主义者，"模型已经训过的东西，对我们没用"。

最有野心的部分是商业模式。广告之所以统治互联网，是因为它极擅长差别定价——多数 Google 查询是亏钱的，少数几个把钱赚回来。但当来访的是 agent 而不是人类眼球，这套假设就塌了。内容方现在唯一可行的选项是跟大厂签一份固定价的年度协议，而"当推理量今年涨 7 倍、明年再涨 7 倍，合起来 50 倍，他们的合同金额并没有涨 50 倍"。Parallel 的解法是 Shapley 值：把某个来源从语料里拿掉，看输出质量掉多少，再看要多花多少算力才能把这份质量补回来——补回来花了一分钱，这个来源就大致值一分钱。理论上算全量 Shapley 值比付给内容方的钱还贵，所以他们训模型来估。这套机制的性质很清楚：数据越独特付得越多；一个银行家读你的内容，比他退休的父亲读，付得更多，因为那是高价值工作的一环。宏观账也算得过来——如果知识工作在 LLM 推理上的花费拿出 2% 到 10% 分给网页数据，就已经远大于今天 Facebook、LinkedIn 这类围墙花园之外的全部网页数据生意。他的判断是：距离这套数学能给相当广范围的内容方带来实质收入，还有 12 到 24 个月。

顺带一个彩蛋：公司最初注册名就叫 Shapley Inc.（shapley.com 是个停靠的色情域名，所以注定不能用），他顶着 "NuCo / Stealth Company" 的活动胸牌过了六到八个月才定下 Parallel 这个名字。

最后是他对未来两年的判断：web 会从 pull 变成 push。今天 agent 都是"现在去帮我找这个"，而未来是"如果世界上发生了这件事，打给我"。他跟团队常说的一句话是：如果一件事今天就能做、值得做、而且还有 GPU，那就今天做完。那明天做什么？明天做的是"响应变化"的活——另一个 agent 的产出、卫星影像里的变化、某条客户评论、一个人的新洞见。而其中一条最重要的 feed，就是整个 web 上刚刚变化的东西。
