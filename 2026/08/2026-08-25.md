### Madhu Guru（Meta AI 资深总监，前 Google，主导过 Gemini / Veo / Nano Banana）

评测系列第 7 篇，讲 eval 构建的「金发姑娘原则」：**你的 eval 应该测在各个 job to be done 的层级上，而不是只测最终答案**。他举了金融分析 agent 的例子 —— 最终产出是一个荐股结论，最常见的错误是团队做一份标准答案集，只检查 agent 有没有推荐「对的」股票。问题在于，得出这个结论之前还有一堆有意义的中间环节：理解客户（持仓、风险偏好、投资期限、目标、约束）→ 收集证据（个股数据、板块、宏观、Fed 政策、新闻事件）→ 分析数据（营收增速、估值指引、增长预测，收敛出候选池）→ 给出建议（标的、买卖价、时间窗）。

每一环都该有自己的 eval。这样最终结论错了的时候，评测集会告诉你：客户理解 92%、证据抽取 92%、数据分析 70%、最终建议 75% —— 一眼就知道该去挖哪儿，甚至能发现「数据分析这步太复杂了，得再拆成更细的 job」。他的收尾很干脆：不要太细，不要太粗，刚刚好，**细到够你诊断和行动为止**。

### Claude Blog

**Building intelligent apps for Apple platforms with Claude in the Foundation Models framework**

Anthropic 发布了一个新的 Swift package，让 Apple 开发者可以在苹果的 Foundation Models framework 里直接调用 Claude。原本这个框架给的是端上模型 —— 快、本地、适合摘要和信息抽取这类活儿；现在遇到需要多步推理、代码生成的请求时，可以直接交接给 Claude，还能让 Claude 联网搜实时信息、执行代码做数据分析，响应流式回到同一个 SwiftUI view 里。

设计上最讨巧的一点是类型衔接：苹果框架通过 `@Generable` 注解返回强类型的 Swift 值，所以「到达 Claude API 调用这一步时，开发者手里拿到的是干净的输入，而不是原始用户文本」。三行代码就能通过 guided generation 拿到 typed 结果。

落到实际形态，官方举的例子很具体：日记类 app 可以在端上生成每日提示，再让 Claude 去跨几个月的条目里找出主线；学习类 app 可以在端上给出术语定义，等学生追问「这为什么对我们学过的其他东西都重要」时再交接给 Claude —— 对用户是一个连续体验，背后每一步用最合适的模型。

支持范围是 iOS 27 / iPadOS 27 / macOS 27 / visionOS 27 / watchOS 27，接进项目、用 Anthropic API key 登录即可，streaming、tool calls、结构化响应都由这个 package 处理。

🔗 https://claude.com/blog/claude-for-foundation-models
