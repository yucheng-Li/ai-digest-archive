## 二、官方博客

### Anthropic Engineering：关于近期 Claude Code 质量反馈的说明
过去一个月大量用户反馈"Claude 变笨了"，Anthropic 追查后确认是**三处独立改动**造成的，全部集中在 Claude Code / Claude Agent SDK / Claude Cowork，**API 未受影响**，三个问题已在 4 月 20 日（v2.1.116）全部修复：

- **3 月 4 日**：为了缓解高 effort 模式下"思考太久、UI 像卡死"的延迟问题，把 Claude Code 默认 reasoning effort 从 high 降到了 medium。这是个错误的取舍 —— 用户明确表示宁可默认更聪明、简单任务再手动降档，4 月 7 日回滚。影响 Sonnet 4.6 和 Opus 4.6。
- **3 月 26 日**：上线了"清理闲置超过 1 小时的会话中旧 thinking"的优化，但 bug 导致这个清理在会话后续**每一轮都执行**，Claude 因此显得健忘、反复啰嗦。4 月 10 日修复。影响 Sonnet 4.6 和 Opus 4.6。
- **4 月 16 日**：加了一条降低啰嗦程度的 system prompt 指令，叠加其他 prompt 改动后损害了编码质量，4 月 20 日回滚。影响 Sonnet 4.6、Opus 4.6 和 Opus 4.7。

三处改动各自影响不同的流量切片、按不同时间表推进，叠加起来就呈现为"大范围、不一致的退化"。Anthropic 也坦承排查困难：三月初就开始看反馈，但一开始难以和正常的用户反馈波动区分，内部使用和 evals 最初都没能复现。原文强调："我们从不会故意让模型变差。" 作为补偿，**4 月 23 日起为所有订阅用户重置用量额度**。
- https://www.anthropic.com/engineering/april-23-postmortem

### Anthropic Engineering：Scaling Managed Agents —— 把"大脑"和"双手"解耦
核心论点：harness（agent 外壳）本质上编码的是"Claude 自己做不到什么"的假设，而这些假设会随着模型变强而过期。文中举了个具体例子 —— Sonnet 4.5 会在感知到上下文快满时提前草草收尾（所谓 "context anxiety"），他们为此在 harness 里加了 context reset；但换到 Opus 4.5 上这个行为消失了，那段 reset 逻辑就成了纯粹的死重。

于是他们做了 Managed Agents：一个托管在 Claude Platform 上、替你运行长周期 agent 的服务，接口设计目标是"活得比任何一种具体实现都久"。方法论直接借鉴操作系统 —— 当年 OS 把硬件虚拟化成 process、file 这类足够通用的抽象，好让还没被写出来的程序也能跑；`read()` 不关心底下是 1970 年代的磁盘还是现代 SSD。同理，他们把 agent 虚拟化成三件东西：**session**（记录一切发生过的事的 append-only 日志）、**harness**（调用 Claude 并把工具调用路由到基础设施的循环）、**sandbox**（执行代码和改文件的环境），三者可以各自替换而互不干扰。

踩过的坑也写得很直白：一开始三者塞在同一个容器里，结果养出了运维意义上的"宠物"而不是"牲口"—— 容器挂了会话就没了，容器卡住只能进去 shell 调试，但那个容器里往往还装着用户数据，等于实际上没法调试。另一个问题是 harness 默认"Claude 干活的东西就在自己容器里"，客户想接自己的 VPC 时就卡住了。最终方案就是标题那句：把"大脑"（Claude 和它的 harness）与"双手"（sandbox 和工具）和"会话"（事件日志）彻底解耦。
- https://www.anthropic.com/engineering/managed-agents

### Claude Blog：Managed Agents 新增自托管 sandbox 与 MCP 隧道（2026 年 5 月 19 日）
Claude Managed Agents 现在可以跑在**你自己控制的 sandbox** 里，并连接你**私有网络内的 MCP 服务**。目前自托管 sandbox 处于公开 beta，MCP 隧道是 research preview（需申请）。

- **自托管 sandbox**：代码执行、敏感文件、依赖包、服务和数据都留在企业边界内，受你自己的安全和运行时管控；负责编排、上下文管理和错误恢复的 agent loop 仍留在 Anthropic 这边，只把工具执行挪到你的环境。你还能自己定 CPU、内存和运行时镜像，长构建、图像生成这类重活儿才有足够资源。支持自带 sandbox 客户端，也可以直接用 Cloudflare（microVM + 零信任密钥注入 + 可审计的出站代理）、Daytona（长跑且有状态，可 SSH 接入、可暂停恢复并完整保留状态）、Modal（亚秒级冷启动、可扩到几十万并发、按需 CPU/GPU）、Vercel（VM 隔离 + VPC peering，凭据在网络边界注入、永不进入 sandbox）。已有客户案例：Amplitude 用它加 Cloudflare 做内部设计 agent，Clay 的 GTM agent Sculptor 跑在 Daytona 上，面向机构金融的 Rogo 在 Vercel Sandbox 上做分析师 agent。
- **MCP 隧道**：让 agent 调用你内网的数据库、私有 API、知识库和工单系统，而不必把它们暴露到公网 —— 部署一个轻量网关，只建立一条**出站**连接，无需开任何入站防火墙规则，流量端到端加密。
- https://claude.com/blog/claude-managed-agents-updates

## 三、播客

### AI & I by Every：《Microsoft's Vision for an Internet Made for Agents》—— 对话微软 CTO Kevin Scott

**一句话要点**：agent 时代真正缺的不是更强的推理，而是一张让 agent 能到处办事的"agentic web"—— 而 MCP 之于它，就是 HTTP 之于互联网。

微软 CTO Kevin Scott 今年在 Build 上换了叙事重心。去年的关键词是 scaling law 和更大的模型，今年他基本不谈了，理由很直接：scaling law 年复一年被验证有效，已经不需要再提醒任何人；反倒是模型的推理能力**跑到了产品前面**——他称之为"能力过剩"（capability overhang），整个行业欠用户一笔账，得把模型已经具备的能力真正兑现到产品里。

真正的瓶颈在别处。一是记忆：现在的 agent 太"事务性"，一个任务内上下文连贯，任务一结束可能就清零，下次从头开始，这从根本上限制了你能把多复杂的活儿托付给它。二是行动力 —— agent 要替你办事，就得能用工具、改系统、查各种信息源，而这需要一个长得很像互联网的生态：你已经有网站、有 API，就得想办法让 agent 也能跟它们说上话，并且让所有人的商业动机都对齐。他把 MCP 类比成这张网上的 HTTP，NL Web 类比成 HTML，认为"简单、可组合、可分层"的开放协议才是正解。

作为 CTO，他在微软内部推的一件具体的事是：所有内部系统对所有内部 agent 都讲同一套标准协议 —— 目的是别把公司的组织架构直接 ship 给用户。"你当然不想在造 agent 的时候把自己的组织结构图发出去。"

安全模型他承认还没有答案，但认为 MCP "简单得足够连贯"，社区有能力自己定下来：agent 需要身份，这样才能建权限体系 —— 这个 agent 代表这个人行事、有权看这些资源；agent 甚至该能主动查询"我要办这件事需要碰哪些系统、需要申请哪些权限"，再回头向用户和管理员要授权。关键是这套东西必须开放，"我们不需要它是我们自己 agent 和系统的专有物"。他也不接受"封闭才安全、开放才创新"这个二分法，认为无需许可（permissionless）的创新恰恰是当下最让他兴奋的事，同时 AI 本身也能带来更强的安全 —— 他举了个自家例子：那天早上他老婆账号的两步验证被人动了，他作为备用安全联系人收到一堆邮件，第一反应是发短信而不是邮件（因为邮箱可能已被入侵），而这类跨渠道的交叉验证，未来完全可以交给一个了解你全部通信渠道的 agent 去做。

关于"agent 写代码是否杀死了工艺感"，这位编程 41 年、同时是木工和陶艺爱好者的老工程师给了最松弛的回答。他坦白自己做着 VS Code，私下却顽固地用 vi，"我知道这在某种程度上是次优的，但我就是要自己选"。他见过太多次同样的争论：当年木工圈吵"用电动工具还算真木匠吗"，今天吵的是"用 CNC 还算吗"。"如果你更看重过程，你会做出和更看重结果的人不一样的选择"——两种都成立。他唯一的建议是保持好奇：他自己拖了很久才学 3D 打印，现在非常后悔，"我早该开始的"。

**"Be curious. Try stuff. And if it works for you, use it. And if it doesn't, don't."**

对未来一年的判断有三条。第一，还在拿"技术还不够成熟、我试过但太贵/差一点"当理由观望的人会被远远甩开，因为每年都会更便宜、更强；押注失败和押注乐观的代价差距太大了。第二，agent 能承接的问题的**野心量级**会大幅上升。第三，交互模式会从同步转向异步 —— 现在人们坐下来发个 prompt 然后干等结果，一年后会变成"你去把这事理清楚"，agent 花很长时间、调用大量系统、反复迭代，过一阵子回来说"我做到这儿了，接下来轮到你了"。

对创业公司他也给了一条明确的判断：现在最有意思的初创公司**不靠差异化的基础设施**取胜，而是因为他们对某个具体问题的理解胜过所有人，然后拿现成的基础设施去改、去调，把这个理解做到世界级。
