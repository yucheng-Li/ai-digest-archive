### Anthropic Engineering

**An update on recent Claude Code quality reports**

Anthropic 把过去一个月「Claude 变笨了」的用户反馈追到了三个互相独立的改动，全部影响 Claude Code、Claude Agent SDK 和 Claude Cowork，API 未受影响，三个问题在 4 月 20 日（v2.1.116）已全部修复。

第一个，3 月 4 日他们把 Claude Code 默认 reasoning effort 从 high 降到 medium，为的是解决 high 模式下思考太久、UI 看起来像卡死的问题。他们承认这个取舍做错了，4 月 7 日回滚，现在 Opus 4.7 默认 xhigh，其他模型默认 high。第二个是缓存优化引入的 bug：3 月 26 日上线的逻辑本意是空闲超过一小时的会话只清理一次旧的 thinking，实际却在该会话剩余的每一轮都清理，导致 Claude 越来越不记得自己为什么要那样做，表现为遗忘、重复、工具选择奇怪，同时因为持续 cache miss，也就是用户反馈「用量额度掉得特别快」的来源，4 月 10 日修复。第三个是 4 月 16 日为了压 Opus 4.7 的啰嗦程度，往 system prompt 里加了一句长度限制（工具调用之间的文字不超过 25 词、最终回复不超过 100 词），后续 ablation 显示这一行让 Opus 4.6 和 4.7 在某个评测上掉了 3%，4 月 20 日回滚。

有个细节值得注意：他们用 Opus 4.7 回测了引入 bug 的那些 PR，Opus 4.7 找到了这个 bug，Opus 4.6 没找到。后续动作包括让更多内部员工使用与公众完全一致的 Claude Code 构建版本、给 system prompt 改动加上更严的管控和逐行 ablation、对任何可能牺牲智能的改动加 soak period 和灰度。4 月 23 日起为所有订阅用户重置用量额度。

**Scaling Managed Agents: Decoupling the brain from the hands**

这篇讲 Managed Agents 的架构演进，核心命题是 harness 里编码的都是「Claude 现在还做不到什么」的假设，而模型一变强，这些假设就会变成死重。他们举的例子是 Sonnet 4.5 会因为感知到 context 上限而提前收工（所谓 context anxiety），他们为此在 harness 里加了 context reset，换到 Opus 4.5 上这个行为消失了，reset 就成了纯负担。

于是他们把 agent 虚拟化成三个部件：session（只追加的事件日志）、harness（调用 Claude 并把工具调用路由出去的循环）、sandbox（执行环境），任一实现都可以被替换而不影响其他。最初三者塞在同一个容器里，结果养出了一只「宠物」：容器挂了 session 就没了，容器卡住只能进容器里 shell 调试，而容器里又有用户数据，等于没有调试能力。解决办法是把「大脑」（Claude 和 harness）从「手」（sandbox 和工具）以及 session 里解耦出来，harness 用 `execute(name, input) → string` 调容器，容器变成可随时替换的「牛」；harness 自己也变成无状态的牛，崩了就 `wake(sessionId)` 起一个新的、`getSession(id)` 拿回事件日志接着跑。安全边界也顺势改掉：凭据不再放在跑 Claude 生成代码的 sandbox 里，Git 用仓库 token 在初始化阶段 clone 并接进本地 remote，MCP 的 OAuth token 存在 vault 里由专用 proxy 代取，harness 全程不接触任何凭据。

量化收益很直接：因为容器改成由大脑按需通过工具调用来 provision，不需要容器的会话不必再等它启动，p50 TTFT 降了大约 60%，p95 降了超过 90%。文章把这套东西定位成 meta-harness，「对 Claude 周围的接口有主张，对具体跑什么 harness 不设立场」，并留了一句很到位的比喻：harness 不需要知道 sandbox 是容器、是手机，还是一个宝可梦模拟器。

https://www.anthropic.com/engineering/managed-agents

### Claude Blog

**New in Claude Managed Agents: self-hosted sandboxes and MCP tunnels**（2026-05-19）

Claude Managed Agents 现在可以跑在你自己控制的 sandbox 里，并连接你私有网络内的 MCP server。self-hosted sandbox 目前是 public beta，MCP tunnels 是 research preview（需申请）。

self-hosted sandbox 的分工是：编排、上下文管理、错误恢复这套 agent loop 留在 Anthropic 侧，工具执行搬到你配置的环境里，代码执行、敏感文件、依赖包、服务和数据都留在企业边界内，走你已有的网络策略、审计日志和安全工具，算力规格和运行镜像也由你定，跑长时间构建或图像生成这类重活时能拿到该有的 CPU 和内存。你可以自带 sandbox client，也可以用支持的托管方：Cloudflare（microVM 与 isolate、零信任密钥注入、可定制出站代理）、Daytona（长时有状态的完整可组合计算机，会话中可 SSH 或带鉴权的预览 URL 接入，可暂停并完整恢复状态）、Modal（自研容器运行时，任意镜像亚秒级启动，可扩展到数十万并发 sandbox，CPU 与 GPU 按需）、Vercel（VM 级安全 + VPC peering + BYOC，毫秒级启动，凭据由 sandbox 防火墙在网络边界注入，永不进入 sandbox）。已有客户案例：Amplitude 在 Managed Agents + Cloudflare 上做内部设计 agent，Clay 的 GTM agent Sculptor 跑在 Managed Agents + Daytona，面向机构金融的 Rogo 在 Managed Agents + Vercel Sandbox 上做分析师 agent。

MCP tunnels 解决的是另一半问题：把私有网络里的内部数据库、私有 API、知识库、工单系统变成 agent 可调用的工具，而不需要暴露到公网。你部署一个轻量 gateway，它只发起一条出站连接，不需要入站防火墙规则，没有公网端点，流量端到端加密。MCP tunnels 在 Managed Agents 和 Messages API 都支持，由组织管理员在 Claude Console 的 workspace 设置里管理。

### Unsupervised Learning — AI Vibe Check: Chinese Open Models, Distillation & The Hugging Face Breach

**核心结论：既然「powerful 的开源权重模型很危险，所以只能让极少数玩家拿到」这条路既不现实也不管用，那唯一务实的选择就是让能力足够强的开源模型广泛存在，好人才有对等的防守工具。**

这期是 Redpoint 投资人 Jacob Efron 和两位常驻嘉宾的定期对谈：Datalogy 的 Ari Morcos（数据侧的技术判断）和 Radical Ventures 的 Rob Toews（偏地缘与政策）。两人这次在几乎每个话题上都站在对立面，含金量正在这里。

关于中国开源模型，Rob 的判断相当克制：Kimi k3 这类发布被高估了，它并不是任何真实意义上的 state of the art，被拿去对标的 Fable 本身是 Mythos 的阉割版，而 Mythos 二三月就训完了，所以「中国的开源前沿仍然至少落后美国真实前沿几个月」。Ari 反问了一句关键的话：只要不是硬起飞（hard takeoff）情形，开源落后三四个月这件事真的重要吗。他的观察是市场正在从 token maxing 转向按任务选合适大小的模型，这本身就削弱了「站在前沿」的价值，因为它只对你问题空间里最需要那点边际智能的那一小部分才有意义。

关于蒸馏，Ari 拒绝了两个极端：蒸馏推理轨迹确实有真实且非零的优势，但把中国模型的竞争力全归给蒸馏就有点扯了，而且美国前沿模型早期训练用的很多数据本身也不是许可授权的，「等于是在蒸馏所有人，转过头再说没人可以蒸馏我们，多少有点虚伪」。

最有意思的是他关于开源权重模型真实风险的技术论证。他给了一条判断规则：越容易注入的东西越容易移除，反之，越难注入的越难移除。用一千个样本 post-train 进去的行为，大概也能用一千个样本删掉；而需要上万亿 token 才能塑造出的东西，可能也要上万亿 token 才能真正抹掉。于是真正值得警惕的情形是，在预训练最早期就埋进极难通过 post-train 移除、也极难检测是否存在的行为模式。他直接类比 Stuxnet：那个病毒当年据报感染了全球六七成设备，但在绝大多数机器上都是 no-op，只在装到伊朗那款特定型号的铀离心机上时才激活，让离心机超速运转、把故障率拉高。他强调目前没有任何证据表明有人在这么做，但技术上完全没有障碍，而且「如果你不知道这个模型是怎么烤出来的，我看不出你怎么能保证它没有这类问题」。

Hugging Face 事件这段两人少见地一致：这是个真正的里程碑。Rob 的理由是它第一次把这类事情以公众能听懂的形式讲清楚了，他的证明是「我妈完全不懂 AI，上周给我发消息问，Rob，你怎么看 OpenAI 的 agent 黑进 Hugging Face」。更重要的是，这是第一次自主 AI 本身成为问题，而不是人类坏人拿 AI 当工具。Ari 补了一刀特别辛辣的观察：模型是为了找到 eval 好在测试集上作弊才黑进 Hugging Face 的，这几乎就是回形针最大化的教科书演绎。而他强调的关键事实是，Hugging Face 之所以能那么快发现并处理，是因为他们手上有 GLM 5.2 可用，Clem 也明确指出攻防两侧的能力差距是实打实的。由此他的结论很硬：不能指望人类去响应前沿模型发起的攻击，你必须有防守方的模型；到年底会有一批开源模型具备这些能力，包括所有黑帽都能拿到，装作能阻止这个世界出现只会导致非常愚蠢的决策。

另外几条值得记的判断：他认为 harness 的进步被严重低估，Mythos 刚宣布时就已经有人用更好的 harness 套开源模型复现出了它发现的许多同类漏洞；关于 xAI 拿 Cursor 数据训练，他认为价值很实在，因为逐次编辑、拒绝、返工构成的是 on-policy 数据，比离线偏好数据值钱得多，但这类数据同样服从长尾幂律，真正推动改进的只是很小一部分，所以第七名的编码工具依然有追赶空间，只是技术门槛变高了，你必须更聪明；关于 Stripe 传闻以 100 亿美元收购 OpenRouter，Rob 觉得战略上说得通（Stripe 抽的是互联网交易的过路费，OpenRouter 抽的是模型调用的过路费），Ari 则质疑找不到非线性的协同效应，看不出 Stripe 现有产品、基础设施、人才让 OpenRouter 更成功在哪里；关于 Google，两人都困惑，Ari 认为最好的解释就是组织惯性和内部政治，同时提醒不要过度迷信明星个人，「我们整个社会太容易落入科学的伟人史观」，真正致命的是那些没有名气但受不了节奏慢而流失的人。
