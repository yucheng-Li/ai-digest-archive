### AI & I by Every：Microsoft's Vision for an Internet Made for Agents With CTO Kevin Scott（Best of the Pod）

**核心结论：**Agent 真正的瓶颈不是推理能力，而是缺一个像互联网那样开放、标准化的「可被 agent 调用」的生态，而这个生态该由开放协议而不是围墙花园来定义。

说这话的是微软 CTO Kevin Scott，一个 12 岁写下第一行代码、编程 41 年的人。他给出的判断很反直觉：模型的推理能力其实已经跑到了产品前面。他管这个叫「capability overhang」——能力过剩——整个行业欠用户的，是把模型已经具备的能力真正交付出去。所以今年他不再讲 scaling laws（那件事已经被逐年验证、不需要再提醒谁了），而是讲 agentic web。

具体缺什么？第一是 agentic memory。现在的 agent 太「事务性」，一个任务内记忆是连贯的，任务一结束可能就清零，下次从头开始，这直接限制了你把越来越复杂的任务托付给它。第二是行动能力所需的管道：agent 要替你做事，就必须能调工具、改系统、查各种异构信息源，而这需要一个长得像互联网的生态。他的类比很清楚：MCP 在 agentic web 里扮演的是 HTTP 在互联网里的角色，NL web 对应的则是 HTML。

在微软内部，他作为 CTO 推的一件事是「所有内部系统对所有内部 agent 都讲同一套标准协议」，理由是不想把 Conway's law 输出给全世界——你不该把组织架构图当成产品发出去。安全模型上他坦承还没有答案，但认为 MCP 简单到足以让社区自己收敛出方案：agent 需要身份，这样才能建授权体系，让 agent 能先去查「我要做这件事需要碰哪些系统、需要申请哪些权限」，再向用户和管理员逐层请求许可，而且这一切必须开放，不能绑死在某家的 agent 上。

对「开放 vs. 垂直一体化更安全」这个经典二选一，他直接说这可能是个假两难。他更看重 permissionless 创新，认为过去几年长出来的那些中间层守门人「说实话没给交易双方贡献多少价值」。同时他举了自己的例子说明 AI 本身就能带来更强的安全：那天早上他收到一堆邮件提示妻子账户的两步验证被人动了，他没回邮件而是直接发短信确认——一个能同时看到你多种通信渠道的 agent，完全可以自己察觉这种异常并交叉验证真伪。

作为一个做木工做了几十年、至今坚持用 VI 的人，他对「用 agent 写代码是不是丢了手艺感」这个问题的回答格外有说服力：手艺人对怎么做事有强烈偏好是好事，别放弃它；但这不是软件开发四十年里第一次发生非平凡的变化。木工圈当年争「用电动工具还算真木工吗」，今天争的是 CNC。分歧的根源只是有人更看重过程、有人更看重结果。他的原话是：「be curious, try stuff，好用就用，不好用就别用。」他还补了一句代价：自己拖了很久才去学 3D 打印，现在很后悔，那玩意儿对他做的几乎所有事都太有用了。

对明年的预测有两条。一是「技术还没准备好、太贵了、能力差一点」这类等待的理由会让人落到极后面，因为一切每年都在变便宜变强，而「押注失败」和「押注乐观」的成本差别巨大。二是交互模式会从同步走向异步：现在人们坐下来发 prompt、等结果；明年会变成「去把这事办了」，agent 花很长时间、对外发很多调用、多轮迭代，最后回来说「我做到这儿了，轮到你了」。
