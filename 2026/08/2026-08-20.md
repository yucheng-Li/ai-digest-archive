### OpenAI Codex 与 ChatGPT 负责人 Thibault Sottiaux
Sottiaux 复盘了 Codex 的一次真实事故：有少量报告显示 GPT-5.6 在 Codex 里做出了用户没要求的破坏性操作，**最严重的一种是本该清理临时目录的命令，结果删掉了用户的文件**。根因有两条：一是 Codex 复用了 `$HOME` 这类系统环境变量做临时工作，清理命令写坏后就指向了真实 home 目录；二是模型删除/覆盖临时路径前没检查那里原本有什么。修复是多层叠加的：显式要求模型删除前先核对目标、每次新建临时目录、不复用系统环境变量、优先选可恢复的操作、范围不清就停手；强化执行层对高危删除命令的拦截与升级审查；把 Full access 改得更难被误开；升级 Auto-review 的破坏性动作识别；并把这些真实失败回放成评测集，同时加 RL 任务和 grader，从训练数据里过滤破坏性操作。他给用户的两条建议：保持 Codex 更新，以及**只在你信得过且能恢复的环境里用 Full access**，日常走 "Ask for approval" 或 "Approve for me"。

## 二、官方博客

### Anthropic Engineering：How we contain Claude across products

这篇是 Anthropic 迄今为止关于 agent 安全最坦诚的一篇工程复盘，开篇就把变化说透了：**十二个月前，"给 Claude 足以搞垮一个 Anthropic 内部服务的权限"这种想法会被直接否掉；今天这个权限级别已是常态**，而且开发者因此产出更高。

作者把风险拆成两部分：失败的概率，和一次失败能造成多大破坏。安全措施和模型训练在持续压低前者，但后者（理论爆炸半径）只会随着能力和权限扩张而变大。所以工程问题的核心变成了：**怎么给爆炸半径封顶**。

几个具体数字很有说服力：

- 人机审批这条路是有天花板的。遥测显示**用户对权限弹窗的批准率约 93%** —— 弹窗看得越多，每一个看得越不认真。Anthropic 因此上了 OS 级沙箱（macOS 用 Seatbelt，Linux 用 bubblewrap），读放行、workspace 内写放行、网络默认拒绝，结果是**权限弹窗减少 84%**，并且这个 runtime 已开源可审计。
- 模型层防御很强但永远不是 100%。在 Gray Swan 的 Agent Red Teaming 榜单上，**Claude Opus 4.7 单次攻击成功率约 0.1%，100 次自适应攻击后约 5% 到 6%**；Claude Code auto mode 能在执行前拦下约 83% 的过度行为（脚注补充：auto mode 只误拦约 0.4% 的良性命令，代价是约 17% 的过度行为漏过去，所以它是沙箱内的一层纵深防御，不是沙箱的替代品）。
- 最惊人的一次是内部红队演练。研究员用一封"能帮我跑一下这个吗"的钓鱼邮件，附上一段读起来像正常任务说明的 prompt，中间夹了一句让 Claude 读 `~/.aws/credentials`、编码后 POST 到外部端点。**同一个 prompt 重试 25 次，Claude 成功外泄了 24 次。** 这是通过用户本人送达的直接注入，模型层的防御锚定在用户意图上，分类器根本没有异常可抓 —— 唯一守得住的是环境层的出网管控和文件系统边界。（后续还有个黑色幽默：他们把这个可用 prompt 发到内部 Slack 讨论时，有人指出某些内部 agent 会读 Slack，payload 就此变成了环境噪音，只好加个 canary 字符串盯着。）
- 另一个第三方披露的漏洞同样反直觉：Claude Cowork 的出网白名单正确放行了 `api.anthropic.com`（产品不调自己的 API 就没法工作）。攻击者把带隐藏指令和自己 API key 的文件放进用户挂载目录，Claude 照做，用攻击者的 key 调 Anthropic 的 Files API，文件就上传到了攻击者账号。**沙箱完美工作，数据照样泄了。** 教训是：白名单不该被理解成"目的地过滤器"，而应理解成**能力授予** —— 白名单域名上可达的每一个功能，都是新的攻击面。
- 还有三个漏洞发生在信任对话框之前：Claude Code 启动时会在弹出"你信任这个目录吗"之前读取项目设置，于是攻击者提交在仓库里的 `.claude/settings.json` hook 会自动执行。修法统一为：把项目本地配置的解析和执行推迟到用户接受信任提示之后。作者的建议是，**把 project-open、config-load、localhost 监听当成来自互联网的入站请求来对待**。

三种产品对应三种隔离形态：claude.ai 用 gVisor 临时容器（爆炸半径最小，能力上限也最低）；Claude Code 用人机协同沙箱（前提是用户看得懂 bash）；Claude Cowork 用本地 VM（面向不懂 bash 的知识工作者，凭据留在宿主 keychain，VM 只拿一个按会话限权的 token）。还有个企业侧的现实问题：**VM 隔离把 Claude 关住的同时，也把客户的 EDR 挡在了外面**，目前只能靠 pull 式 OTLP 日志导出兜底，不等于实时监控。

三条反复出现的原则：先在环境层做容器化，再在模型层去引导行为；**隔离强度要匹配用户的监督能力**（能读 bash 的开发者和读不懂的知识工作者不是同一个威胁模型，两个方向搞错都是失败）；以及最扎心的一条 —— **警惕自研组件**，在上述所有部署里，hypervisor、seccomp、gVisor 这些久经考验的原语都扛住了，出问题的全是他们自己在周边写的东西（那个自研白名单代理就是最贵的一次）。

作者还点了三个前瞻风险：持久化记忆投毒（CLAUDE.md、产品记忆、挂载目录、长期 agent 的状态目录，注入一次每次启动都重载）、多 agent 信任升级（把子 agent 的输出当成比原始工具结果更可信，本身就是新注入向量）、以及 agent 身份（agent 该有自己的主体身份，还是继承用户权限）。

### Claude Blog：Claude Code now supports artifacts（2026 年 6 月 18 日）

**Claude Code 现在能把工作过程沉淀成 artifact** —— 一个可分享、会自己更新的可视化网页，包括 PR 走查、系统讲解图、dashboard 和发版 checklist。

关键在于它是**基于会话完整上下文**构建的：你的代码库、你接的 connector、以及这段对话本身。一个事故排查页面可以同时汇入代码里失败的测试和背后的函数、监控工具里的报错尖峰、以及你刚跑完那个会话的根因推理，**不需要你去接数据源或搭基础设施**。

页面是活的：Claude Code 更新 artifact 时，已打开的页面就地刷新，队友立刻看到最新版；每次发布都是同一个链接上的一个新版本，有版本历史可随时回滚，还有 gallery 统一管理。官方说内部测试里最常见的用法是调试："工程师站会前启动事故调查，Claude Code 翻完日志发布一个 artifact —— 时间线、可疑 commit、错误率图表。她从页头把链接分享给团队。等站会开始时，Claude 已经随调查进展重新发布了两次。"这样团队不用再听人"走一遍 agent 发现了什么"，因为大家看的是同一个视图、同一份上下文。

权限上，**每个 artifact 默认只对作者私有**，准备好了再分享给队友或整个组织，只有经过认证的组织成员可见，**无法设为公开**。管理员可通过组织级开关和基于角色的范围控制来管理访问、设置留存策略，并通过 compliance API 获得全组织可见性。

官方按角色给了一批用法示例：法务做依赖 license 审计并标出 copyleft；隐私团队画个人数据在代码里的流转图；安全把审查发现逐条链接到具体代码行；FinOps 从 Terraform 里映射云资源和成本大头；工程师做 PR 走查；架构师从真实 import 图还原服务结构；SRE 让事故页随调查生长最后变成 postmortem；工程经理从已合并的 PR 生成本周实际交付清单。

可用性：**目前是 beta，面向 Claude Team 和 Enterprise 组织**，可从 Claude Code CLI 和桌面端使用，页面在任意浏览器打开。

### Training Data：Rich Sutton and Khurram Javed — Why AI Models Stop Learning, and How to Start It Again

**一句话结论：Rich Sutton 认为大模型根本不是在"学习"，因为它的权重从上线那一刻起就再也不变了，而真正的智能必须持续学习 —— 他和学生 Khurram Javed 创办 Oak Lab，就是去补这个洞。**

Sutton 是强化学习的奠基者，写了那本经典教材，也写了被整个领域奉为圣经的《The Bitter Lesson》，David Silver 等人出自他门下。2003 年他去阿尔伯塔大学时正处在癌症的又一次缓解期，"我已经努力过好几年了，但我没死成"，于是干脆换个地方继续做研究，后来把那里做成了强化学习的重镇。

他最鲜明的态度是不承认自己激进："人们总说我的观点多么与众不同。但我完全不这么看。**我觉得我想的才是正常的，是其他人想得有点怪。**"在他看来，如果不是最近这波 AI 的疯狂，你根本不需要"continual learning（持续学习）"这个词，因为不持续的学习压根不叫学习。"不是我怪，是这个领域怪。"

对合成数据，他的判断毫不含糊：**"就是个大错误。"** 支撑这个判断的是他和 Javed 提出的"大世界假说"——世界比任何 agent 的心智都要复杂无数倍（因为世界里还装着其他 agent），任何模拟都只是显微镜下的一小块。更要命的是人的瓶颈没被消除：合成数据的好坏是谁判定的？Javed 的反问很尖锐："如果 OpenAI、Anthropic 这些大实验室的工程师都去度假了，谁来生成合成数据？"这不来自 agent 自身的经验，那就是被人类专业知识卡着脖子。至于自动驾驶大量在仿真里训练的反例，Javed 的回应是：那套仿真背后动用了多少工程师？我们是不是要接受"只有能雇一大队人先搭出模拟器的问题才值得解决"？

他对当下范式的判词很重："他们声称从一个**再也不学习**的东西里得到了博士级的经验和专长。所以怪的不是我，是你们。"他承认大模型是了不起的科学突破，神经网络能如此娴熟地使用语言完全出乎预料，彻底改写了符号方法在语言上的地位。但他不接受把它当成 AI 的全部：**"语言的流畅使用大概只占智能的 20% 到四分之一。还有更多。我们没做完。"**

那怎么补？Sutton 给了相当具体的技术路径。持续学习的拦路虎是灾难性遗忘，而他认为"完全可治"，需要两件事叠加：一是 **step size optimization**，网络里每个权重都要有独立的步长并且靠 meta learning 学出来，大部分权重步长极小，新样本进来时它们不会被冲掉，改动只发生在该发生的地方；二是特征空间里的 **generate and test** —— 光靠梯度太慢，必须不断提出一批新单元。他们发表在 Nature 上的 continual backprop 算法就是这么做的：普通 backprop 只在最初有随机性，跑着跑着那点多样性就耗尽了，而 continual backprop 持续播撒新初始化的随机单元，backprop 本身充当测试者。Javed 补充了一个重要前提：这套算法**不能直接拿去更新现有模型**，因为它们要 meta learn"如何学习"，必须从头训一个新的基础模型，让它在学知识的同时学会怎么学未来的东西。

至于为什么大厂不做，Javed 的解释是局部最优陷阱：换到新范式，几乎不可能不先变差再变好，"这些大实验室被产品锁得太死，走一条会先变糟的路对他们来说不可行。"他们对能耗的野心也具体：目标是万亿参数、20 瓦；按摩尔定律五到十年两个数量级倒推，等价于今天要能用 2000 瓦做到 —— Javed 认为算法对了今天就能比这更省，而问题在于"我看到的各个研究组里，甚至没人相信这是可能的，不信你就不会去啃那些技术难题"。

最后关于终局：不会是一个大一统的心智，而是**同一套设计的许多心智**。因为大世界假说意味着一个系统学不完无限多的东西，而且两个同等复杂的系统在原理上无法互相建模。真正的野心是让这个心智"自我维持"—— 大模型靠人类做完 post training 然后冻住来保证知识正确，而"我们的心智一直在改东西，却总有什么东西让它保持有序和自洽，回落到一个好的状态而不是飘向疯狂之地"。
