### 1. Anthropic Engineering：关于近期 Claude Code 质量下降的复盘
**链接**：https://www.anthropic.com/engineering/april-23-postmortem

过去一个月很多人吐槽 "Claude 变笨了"，Anthropic 这篇 postmortem 把锅一次性认了：**三个独立改动叠加，造成了看起来"全面退化"的错觉**，API 本身没被影响，全部已在 4 月 20 日 v2.1.116 修复完，并对所有订阅用户重置了 usage limits。

三个 bug 分别是：

- **3/4 默认 reasoning 从 high 降到 medium**——为了缩短"UI 看起来冻住了"的高延迟，结果用户更在乎智力而不是速度。4/7 已回滚，Opus 4.7 现在默认 xhigh，其余默认 high。
- **3/26 缓存优化误删 thinking history**——本来想做的是"session 闲置一小时后清掉旧 thinking 省 cache"，bug 写成"每一轮都清"，所以 Claude 会越聊越失忆、重复、瞎选工具。4/10 修复。
- **4/16 注入了一条"少废话"系统提示**——和别的 prompt 改动叠加后让编码质量下降，4/20 回滚。

Anthropic 反思了为什么内部 eval 没复现：三个改动各影响不同流量切片、不同时间，**汇总信号是"模糊广谱退化"，eval 设计不擅长抓**。承诺以后更早把用户报告和量化指标关联起来。

### 2. Anthropic Engineering：Managed Agents——把"大脑"和"双手"解耦
**链接**：https://www.anthropic.com/engineering/managed-agents

Anthropic 正式上线 **Managed Agents**：托管在 Claude Platform 上、替你跑长时任务的 agent 服务。这篇文章解释了它的**架构哲学**——像当年操作系统把硬件虚拟化成 process / file 一样，Anthropic 把 agent 也虚拟化成三个独立组件：**session（追加式事件日志）、harness（调用 Claude + 路由工具）、sandbox（执行环境）**，每一个都可以独立换掉。

最反直觉的洞察："**harness 编码的是 Claude 当下做不到的事，但模型一升级这些假设就过期**。"举例：Sonnet 4.5 有"context anxiety"（快到上下文上限就草率收尾），harness 加了 context reset 修复；换到 Opus 4.5 这毛病没了，reset 就变成 dead weight。所以 harness 必须能频繁换掉。

具体做法是 **把"大脑"（Claude + harness）和"双手"（sandbox）分开**——harness 离开 container，通过 `execute(name, input) → string` 像调工具一样调 container。原来 container 是"宠物"（坏了就丢失 session、还得 nurse 回来），现在变成"牛"（坏了就 catch error、retry 时拉一个新的）。harness 自己也变成牛，crash 后用 `wake(sessionId)` 拉新实例 + `getSession(id)` 重放事件日志。

安全侧的收益最关键：**老架构里 Claude 生成的不可信代码和 credentials 在同一个 container，prompt injection 拿到一次 token 就能开新 session 撬动一切**。新架构把 token 放在 sandbox 外的 vault，Git push/pull 走预初始化的 remote，agent 全程碰不到 token。

### 3. Claude Managed Agents 更新：自托管 sandbox + MCP 隧道
**链接**：https://claude.com/blog/claude-managed-agents-updates

紧接上一篇，今天 Managed Agents 又开放了两个企业向能力：

- **Self-hosted sandboxes（公测）**：agent loop（编排 / context / 错误恢复）仍跑在 Anthropic，但**工具执行 sandbox 可以放在你自己的 infra 或托管在 Cloudflare / Daytona / Modal / Vercel**。敏感文件、包、内部服务不离开企业边界，资源大小和镜像你自己定。
- **MCP tunnels（research preview，申请制）**：让托管的 agent 通过加密隧道连你内网里的 MCP server，不用把内部服务暴露到公网。

四个 sandbox 合作伙伴各有侧重：Cloudflare 用 microVM + zero-trust secrets injection 跑批量，Daytona 是"完整有状态的电脑"可 SSH/暂停恢复，Modal 适合 AI workload，Vercel 走自家平台原语。Amplitude 的内部 Design Agent 用的 Cloudflare 组合，Clay 的 GTM agent Sculptor 用的 Daytona。

### 4. Claude 新增"生活类" connectors
**链接**：https://claude.com/blog/connectors-for-everyday-life

Claude directory 自 2025 年 7 月上线以来 connectors 数量破 200。今天再开一批**消费/生活向**接入：AllTrails、Audible、Booking.com、Instacart、Intuit Credit Karma、Intuit TurboTax、Resy、Spotify、StubHub、Taskrabbit、Thumbtack、Tripadvisor、Uber、Uber Eats、Viator。

更值得注意的是**新交互范式**：connectors 现在**动态出现在对话中**——Claude 根据你说的话主动推荐合适 app（"周末去哪 hike？"→ AllTrails 跳出来），多个 app 都能回答时把候选都列出来让你选。Anthropic 强调三条边界：**无广告、无付费排序、connector 数据不用于训练；下单/支付前必须再次确认**。

PM 工作流的例子很 telling：从 Amplitude 拉 query → 转成 Canva slide → 丢链接到 Asana，整个流程不离开对话。

### AI & I（Every）— Dan Shipper：我们把一切都自动化了，但 headcount 翻了三倍
**链接**：https://www.youtube.com/watch?v=dCmOTURRf1Y

**The Takeaway**：**"骑着模型走（ride the models）你就没事"——agent 越远离人类就越没价值，最佳生存策略不是被取代而是当那个一直被回头问"接下来做什么"的人。**

Dan Shipper 是 Every 的创始人 / CEO，COO Brandon 反过来采访他刚发布的 *After Automation*。Every 是公认 AI 最 native 的内容公司——"Slack 里随便挥一棍打到的人和 agent 概率一样"，全员重度使用 Claude Code 和 Codex。但悖论是：**从 GPT-3 时期 4 个人扩张到现在 30 人，还在继续招**。Dario 喊"入门级白领要被砍一半"、Ken Griffin 看完 AI 跑数据连连惊叹的时候，Dan 想说点别的。

**核心反直觉论断**：

1. **Agent 越远离人类越没价值**。把任务交给 agent 跑完丢出来的产物质量普遍"还行、相似、不够贴合具体情境"，**结果是 expert 的稀缺度反而上升**——只有专家能让 agent 的产出真正契合活的情境。
2. **Zeno 悖论式的追赶**：模型在 benchmark 上指数级进步，但**饱和一个 benchmark 后非常容易再 unsaturate**——稍微换个略大略广的 frame，分数就归零。"你说人能做什么 AI 不能做的，一旦说清楚了 AI 就能 hill climb"，所以人和 AI 之间真正的差距永远是**那些没法被清晰表达的东西**。
3. **Agent ≠ agency**。"agent 是替别人做事的东西"，可以非常自主地执行任务（包括"反对我说的每件事"这种任务），但**没有任何小孩都有的那种"自发想做某件事"的内驱**——而整个产业都在朝"更顺从"的方向走，没人有动力让 agent 自己罢工去玩。
4. **客服被裁案例的 Reddit 调研**：Dan 用 Codex + Claude Code 爬遍 Reddit 客服话题，发现**多个公司大裁客服→两个月后哭着请人回来**。两个原因：（a）实施得太烂；（b）**打电话的人就是要找真人，会主动套话验证你是不是机器，是机器就要"a fucking human"**——这是 AI 落地最被低估的物理阻力。
5. **怼"ClickUp 那种 CEO"**：拿"业务历史最好+裁 8000 人"两件事一起 brag 没品味；Jensen 那句"如果你的进步方式是裁人，你不是个有创意的 CEO"虽然 self-serving 但 Dan 同意。AI 时代会有**大规模组织结构重组**，但"AI 取代工作"是个太干净的叙事，往往掩盖了"公司本来就经营不好+借 AI 甩锅"的真相。
6. **AGI 的工作定义**：**"任何一个你永远不需要关掉的 agent"**——一直在生成 token、一直在做事、运行成本上经济可行。Dan 认为即使 AGI 来了仍然是"回头问你要不要"，因为整个进步方向都被推向"回头看你想要什么"。

**写作工作流彩蛋**：这篇 8000 字 *After Automation* 写了 4-5 个版本。Dan 的方法是每天早上**对着电脑空口独白当天的论点**，然后让 Claude（他认为做 thinking 比 Codex 强）来回怼"你真正想说的是什么"。后期把每天的草稿交给 Codex 转成**音频播客**，上班路上反复听、捕捉违和点。

最终金句他自己复述："**If you ride the models, you're going to be okay. You'll have a job, you'll do great work, and you don't have to worry.**"
