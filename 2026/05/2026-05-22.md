### AI & I by Every — Inside Stainless: The Developer Tools Startup Anthropic Just Bought for $300 Million

**The Takeaway**：MCP 的真正未来不是把 API 拆成几百个小工具喂给模型，而是让模型自己写代码、在受控沙盒里跑——以最少的 context 实现最大的能力边界。

Stainless 创始人兼 CEO Alex Rattray 刚刚被 Anthropic 以 3 亿美金收编。Stainless 给 OpenAI、Anthropic 等所有头部公司做 SDK 和 API 工具，是几乎所有 AI 公司背后的"水管工"。他在被收购前几个月接受 Dan Shipper 访谈，毫无保留地拆解了 API/SDK/MCP 的设计哲学和他对 Agentic AI 未来的判断，视角具有罕见的全局性。

Alex 抛出的最反直觉判断："code execution tool 会成为最被广泛使用的工具"。今天大部分 MCP 失败是因为：要把整套 API 翻译成上百个工具直接塞给模型，光描述就烧光 context window，模型还容易迷糊。他的解法是 dynamic mode——不管 API 多大，只给模型三个工具：list endpoints、get endpoint、execute endpoint。但终极形态是再进一步，让模型在沙盒里直接写 TypeScript，调用 stripe.transactions.list、stripe.refunds.create，跑完只把 console.log 的几行结果带回，"the context hit coming back from all of this is going to be like 10 lines of text"。

他对 MCP 安全的判断同样精准：当下大家把权限边界画在 MCP 层是错的，必须画到 API 层——通过 OAuth 的细粒度 scopes，否则 agent 总能绕过 MCP 直接打底层 API。

最让人有共鸣的是他在内部业务中的实践：让 Claude Code 一直跑在他电脑上，把客户证言、SQL 查询、客户支持工单的修复尝试统统沉淀到一个 Git 仓库里。"Cloud Code can handle unstructured stuff really well"——不要过早设计结构，让 AI 自己处理混乱。这是公司"大脑"的雏形。

他对 MCP 设计的口诀很值得抄走：工具数量要少、工具名和描述要精准、输入参数要少而清晰、返回数据要刚好够用。"Good writing is hard."
