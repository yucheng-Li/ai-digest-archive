### The MAD Podcast with Matt Turck — Why AWS and Azure Cannot Run Autonomous AI – Ivan Burazin (Daytona)

**一句话总结**：AWS / Azure 这些 hyperscaler 是为「无状态、长期不变的 web 应用」造的，而 AI agent 需要的是「有状态、可以暂停 / fork / 即开即用、随时扩容的私人电脑」，这是一个全新的基础设施品类——sandbox。

讲话的是 Daytona CEO Ivan Burazin。在做 Daytona 之前，他和联合创始人 2009 年就在搞 Cloud IDE（CodeAnywhere）——比 Docker、Kubernetes、VS Code 都早。这次他们不再做应用层，而是直接做 agent 时代的底层 compute。

Ivan 的核心论点是「**每个 agent 都至少需要一个 sandbox，有时候不止一个**」。他给了一个非常具体的例子：做董事会 PPT 时，他让 Claude 去银行取数据，Claude 说「你给我登录权限就行」——「我说『登录给你权限？不可能。』那一刻整个 thesis 就崩了。」解决办法是给 agent 自己的机器、自己的银行账号、自己的手机号做 2FA，**像对待数字员工一样给它配工卡**。

他对 sandbox 的定义是「composable computers for AI agents」——分三层：infrastructure（启动速度 60ms，1.5 分钟拉起 5 万台，单客户日活账面上百亿次），primitive（Firecracker / Cloud Hypervisor / QEMU / Sysbox 容器都支持，按 use case 切换），tooling（headless 终端、文件操作、secrets 管理、firewall 等护栏）。

非常反直觉的几个细节：
- **他们扔掉了 Kubernetes**，自己写调度器。「现成的调度器都是为快进快出的 Lambda 函数设计的——但 sandbox 凭什么默认要 ephemeral？你笔记本不会自动死。」
- 他们也不用网络盘，而是直接把硬盘挂在物理机上——IOPS 从「几十万」涨到「几千万」，但运维复杂度翻倍。
- 给搞 RL 的客户的需求已经压到「**500 万并发 sandbox**」级别——CPU box 启动越快，昂贵的 GPU 空转越少。
- Ivan 引用 SemiAnalysis 的 Dylan Patel 给出的判断：**到大约今年 10 月，全球可能进入 CPU 短缺周期**——agent 的 CPU 消耗已经被严重低估。

最戳人的一句话，也是他这次的爆款 tweet：「**如果你打算在这个 super cycle 里休假，你就是在喂市场（you're feeding market）**」。被骂了一遍后他发现：哪怕用户激烈反对你的观点，只要他们真的需要你的产品，照样会变成付费客户——「**有反对声的 awareness 仍然是 awareness**」。

最后他对模型架构的判断也值得记一笔：「我对『当前 transformer 就是终局』这种想法非常警惕——我不觉得这是真的。」他提到果蝇脑被 wetware 复刻后能在电脑里玩 Doom，「能否复刻一个通用人类大脑？我说的不是明天，但这是个真问题——一旦发生，所有人的押注都要重写。」
