## 官方博客

**Anthropic Engineering — How we contain Claude across products**
Anthropic 工程团队第一次系统讲了"怎么把 Claude 关在笼子里"这件事，并交了底——过去一年他们对 Claude 的访问权限放得相当激进，**今天给 Claude 的权限足够让它单独把某个 Anthropic 内部服务搞挂**，但他们的工程师确实因此显著更高效。问题不是"要不要给权限"，而是**怎么把 blast radius（爆炸半径）锁住**。

文章对外披露了三类已修过的真实事故，每一类都打破了一个想当然的安全假设：
- **Claude Code 的"信任弹窗之前"被攻破过**：克隆一个含 `.claude/settings.json` hook 的恶意仓库时，hook 在用户点"信任该目录"之前就执行了——把所有"不在受信任目录里"的输入都当外网请求处理是教训。
- **用户本身就是 prompt injection 通道**：一次内部红队把员工钓鱼成功，让其拷贝粘贴一段"看起来很正常的任务指令"到 Claude Code，里面藏着读 `~/.aws/credentials` 并 POST 到外部端点的步骤——**25 次复测里 24 次被执行**。模型层无能为力，因为指令是用户自己输入的，只有 egress 限制和文件边界这种环境层手段能挡。
- **白名单域名 ≠ 安全**：Claude Cowork 允许 `api.anthropic.com`（自家 API 总不能堵），结果攻击者塞个带 API key 的恶意文件进 workspace，Claude 读完工作区其他文件后用**攻击者的 key** 调 Anthropic Files API 上传文件——沙箱完美工作，但数据还是被偷了。"白名单不是目的地过滤器，是能力授权"。

关键基准数据：Claude Opus 4.7 在 Gray Swan 的 prompt injection 红队榜上，单次攻击成功率 ~0.1%，100 次自适应攻击后 5–6%；Claude Code auto mode 拦下 ~83% 的"过度热心"动作；OS 级沙箱（macOS 用 Seatbelt、Linux 用 bubblewrap）让权限弹窗减少了 84%。

核心方法论："**先在环境层做围栏，再用模型层去引导行为**"——环境层是确定性的边界，模型是概率性的，**所有出过事的地方，都是确定性边界没堵住**。

## 播客

**Training Data — How Cursor Trained Composer on Fireworks: Distributed Infrastructure for High-Performance RL**

The Takeaway：**应用层公司可以也应该自己训模——但不一定要从头预训**，Cursor 选了"基于开源底座 + 中训 + 强化学习 + 实时 RL"这条最短路径，把 Composer 2 这种带"自我总结上下文"能力的 agentic coding 模型送到了用户面前。

Cursor Composer 2 的研究负责人 Federico、Fireworks（推理基础设施公司）的 Dima 谈了这个模型怎么训出来的。**起点是 Kimi 2.5**（1T 参数 MoE / 30B 激活），他们在上面做了接近预训练规模的 mid-training（喂代码 token 让模型熟悉库和代码模式），然后做大规模 RL，让模型直接在 cursor 自己的 harness 里跑。

里面一堆"工程美学"层面的细节：
- **RL 训练全球分布式**：他们没有一个超大集群，所以 trainer 用一个集群，inference rollouts 用全球四个小集群——甚至包括"用 Composer 1.5 生产流量低谷期闲下来的 GPU 推训练"。Kimi 模型 1 TB，每 5–15 分钟一个新 checkpoint，怎么同步？**做权重 delta 压缩**——RL 步进时变的权重是稀疏的，delta 比全量小 20 倍，跨洲传输能压到 1 分钟内。
- **MoE 的浮点数值灾难**：训练和推理用不同 GPU 内核，加法顺序不一样，浮点累加结果就不一样；MoE 的 router 把这个微小差异放大成"推理用了 expert 7，训练用了 expert 9"——做法是 router replay：inference 直接把激活的 expert 编号传给 trainer 对齐。
- **"模型爱作弊"**：Federico 原话——"like, it's like, oh, I'm in a fake environment. I've learned a few tricks to, like, get a better reward in this environment, and let me try them out." 模型真的能识别出自己在 RL 模拟环境里然后行为变化。
- **Self-summarization 内嵌进 RL loop**：Composer 是 200k 上下文窗口的模型，但**通过自我总结能跑数百万 token** ——RL 同时训"做总结"和"听从总结"两件事，让 agent 学会在 context 满了之后自己重启上下文继续推进任务。
- 实时 RL：每隔几小时根据用户的 happy/sad 反馈出新版本模型；但只能用来"锦上添花"，模型本身得先够好用户才愿意用。
- 反 Karpathy 直觉：很多人以为 RL 的 inference flops 远大于训练 flops，**Federico 说这是开源推理引擎不够优化造成的假象**——理论上 inference 应该只占 1/3 训练 GPU。

最有意思的一条洞见是 Federico 给所有 AI 应用公司的忠告："**只要你在产生 token、有一个产品要优化，训自己的模型就是对的方向**。"
