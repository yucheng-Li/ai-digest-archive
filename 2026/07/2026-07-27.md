### Vercel CEO Guillermo Rauch

今天最成体系的一组表达。他的核心论点是「软件工厂本身才是产品」：你的产品好不好，取决于你搭起来的那套能自主维护它的 agent 有多好。他把这个类比到 Tesla，说 Elon Musk 早就在制造业想明白了这件事，现在轮到软件行业。所以当你有一个新点子时，不该想「我去找个 agent 随手 prompt 一下」，而该想「我怎么建一个能启动、维护并让这个点子长大的工厂」。

他还分享了自己的实际工作流：所有 research 都用 agent CLI 加文件系统完成。一个 `research/` 文件夹，一份 `AGENTS.md` 写清楚他要的格式和最佳实践，然后启动 agent 直接问。不用花哨的 App、知识图谱或 UI，agent 可以自己去关联历史 session 里的知识，文件夹用 iCloud 或 git 同步就行。他的原话是「Scales to infinity」，驱动这套东西的「软件」其实就是 `AGENTS.md` 里的英文。

### Anthropic Engineering：关于近期 Claude Code 质量反馈的说明

https://www.anthropic.com/engineering/april-23-postmortem

一份罕见坦诚的故障复盘。过去一个月用户抱怨 Claude 回答变差，Anthropic 追查后确认是三个独立改动叠加所致，影响 Claude Code、Claude Agent SDK 和 Claude Cowork，API 未受影响，三个问题都已在 4 月 20 日（v2.1.116）修复。

三个原因分别是：3 月 4 日把 Claude Code 默认 reasoning effort 从 high 降到 medium，为的是缓解 high 模式下延迟长到 UI 像卡死的问题，事后承认「这个取舍做错了」，4 月 7 日回滚，影响 Sonnet 4.6 和 Opus 4.6；3 月 26 日上线了一个清理闲置超过一小时 session 中旧 thinking 的改动，但 bug 导致它在后续每一轮都执行，让 Claude 显得健忘且啰嗦，4 月 10 日修复；4 月 16 日加了一条降低啰嗦度的 system prompt 指令，与其他 prompt 改动叠加后伤到了编码质量，4 月 20 日回滚，影响 Sonnet 4.6、Opus 4.6 和 Opus 4.7。

关键在于三个改动各自影响不同的流量切片、按不同时间表推进，叠加起来就呈现为「大面积且不稳定的退化」。Anthropic 也承认排查滞后：3 月初就开始看反馈，但一开始很难和正常的用户反馈波动区分，内部使用和 eval 最初都没能复现。作为补偿，4 月 23 日起为所有订阅用户重置用量额度。

### Anthropic Engineering：Scaling Managed Agents，把大脑和双手解耦

https://www.anthropic.com/engineering/managed-agents

这篇的核心洞察是：harness 本质上编码了「Claude 自己做不到什么」的假设，而这些假设会随模型变强而过期。文中举了个具体例子，Claude Sonnet 4.5 会在感觉快到 context 上限时草草收尾，业内叫「context anxiety」，他们为此在 harness 里加了 context reset；但同一套 harness 用在 Claude Opus 4.5 上，这个行为消失了，reset 就变成了死重量。

于是他们做了 Managed Agents：Claude Platform 上托管的长周期 agent 服务。设计思路直接对标操作系统当年解决的问题，也就是如何为「尚未被设想出来的程序」设计系统。就像 `read()` 不关心底下是 1970 年代的磁盘还是现代 SSD，他们把 agent 虚拟化成三个组件：session（记录一切的 append-only 日志）、harness（调用 Claude 并把工具调用路由到基础设施的循环）、sandbox（Claude 跑代码改文件的执行环境）。

早期他们把三者塞进同一个容器，结果养出了「宠物」而不是「牲口」：容器一挂 session 就没了，容器无响应就得人工抢救，而唯一的观察窗口只有 WebSocket 事件流，harness 的 bug、事件流丢包、容器掉线三种情况看起来一模一样。更麻烦的是，工程师要排查就得进容器开 shell，而容器里往往还装着用户数据，等于事实上没法调试。解耦「大脑」（Claude 和 harness）与「双手」（sandbox 和工具）之后，每一层都能独立失败或替换。

### Claude Blog：Managed Agents 新增自托管 sandbox 与 MCP 隧道

https://claude.com/blog/claude-managed-agents-updates

上一篇的产品落地。即日起 Claude Managed Agents 可以跑在你自己控制的 sandbox 里，并连接你的私有 MCP server。自托管 sandbox 目前是 public beta，MCP 隧道是 research preview（需申请）。

自托管 sandbox 的意义是：代码执行、敏感文件、依赖包、服务和数据全部留在企业边界内，受你自己的安全和运行时管控；负责编排、上下文管理和错误恢复的 agent loop 仍跑在 Anthropic 这边，只把工具执行挪到你的环境。算力也归你控制，资源规格和运行时镜像都在你这边设置，跑长时间构建或图像生成这类重活时能给足 CPU 和内存。

支持的托管方各有侧重：Cloudflare 用 microVM 和轻量 isolate 做规模化，出站请求可控，支持零信任密钥注入；Daytona 的 sandbox 是完整可组合的计算机，长时运行且有状态，session 期间可通过 SSH 或带鉴权的预览 URL 访问，也能暂停后带完整状态恢复；Modal 的自定义容器运行时能在任意镜像上做到亚秒级启动，可扩展到数十万并发 sandbox；Vercel 则结合 VM 安全、VPC peering 和自带云，毫秒级启动，凭证在网络边界注入，永不进入 sandbox。已有 Amplitude、Clay、Rogo 等公司在上面搭内部 agent。

MCP 隧道解决的是另一件事：让 agent 连上私有网络里的 MCP server 而不必把它暴露到公网。你部署一个轻量 gateway，它只发起一条出站连接，不需要入站防火墙规则，没有公网端点，流量端到端加密。内部数据库、私有 API、知识库和工单系统就此变成 agent 可调用的工具。

### Unsupervised Learning Ep 91：顶级 AI 分析师拆解当下的 AI 炒作周期

https://www.youtube.com/watch?v=vDY_ocrkQ5w

**一句话结论：** 现在几乎所有关于 AI 会取代什么工作的分析，方法论上都站不住脚，因为你既没法量化一个人的工作到底是什么，也没法量化模型到底能做什么。

Benedict Evans 是前 a16z 合伙人、如今独立写作的科技分析师，以年度技术趋势演示著称。他在 Redpoint 投资人 Jacob Efron 面前给出的是一个刻意「不激动」的视角：AI 和互联网、移动一样是大事，但未必是工业革命级别的文明改写。

他最反感的是那类雷达图式的岗位影响分析。「Opus 8.6 能做一年级律所助理 93% 的工作」这种说法在他看来是妄想，「因为你没法那样测量律所助理在做什么，你也没法测量模型能不能做到。」他把这归为「专家系统谬误」，就是当年人们以为能说清自己是怎么分辨猫和狗的那种错误。他还提醒，真正的冲击往往来自分析框架之外：互联网完全没改变记者这个职业的内容，却摧毁了本地广告生意，而那根本不在任何人的分析表里。

对「自动化会一路吃到顶」的说法，他的反驳是历史数据。整个二十世纪美国会计师人数是一条笔直向上的线，中间穿过打孔卡、加法机、大型机一轮又一轮自动化。但他不认为这是 Jevons 悖论那么简单：今天在 PwC 干了五年的人，并不是在做 1970 年同岗位的事情只是做得更多，而是「你当年做的那些事，现在变成每周花十秒钟」。

关于模型公司的护城河，他给了一个刻意拧巴的判断：SpaceX 在完全掉队之后又几乎跳回排行榜顶部，这对 SpaceX 是个负面信号。理由是这说明只要你肯花几十亿美元、招对人，这事就没那么难，目前还看不到搜索、社交、移动那种级别的进入壁垒。他也提醒别高估编程这个突破口，「编程其实是个挺小的行业」，而这轮平台转移与以往最大的不同是它更贵而不是更便宜、有实实在在的边际成本，所以你没法先做个消费级 App 攒一亿用户再想收入模型，这也是为什么一切都涌向企业侧。

最尖锐的一段是他对使用深度的判断：现在只有一成到一成五的人算日活，而且日活也就是一天用一两次，另有两三成是周活月活。「你从社交那会儿就该记得，周活用户是扯淡。」

他留的最后一个故事是 1999 年：他所在的银行去看一家从目录零售转型的电商公司 IPO，营收一亿英镑却想按七八亿估值上市。一车人在回程火车上争论创始人、董事会和估值，一位叫 David Tate 的老银行家睁开一只眼说了句「低毛利的经销商，一次性销售」，然后继续睡。「有时候事情就是这么简单。」
